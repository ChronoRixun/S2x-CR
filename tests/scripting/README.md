# Server scripting regression checks

Build `storage.vcxproj` with VS 2022 C++ tools, then run `build/tests/scripting/bin/storage.exe`. The test includes the production storage header, uses a unique temporary directory, and covers valid text/empty files, absent files, path and device-name rejection, size/NUL limits, symbolic links, atomic replacement and locked-destination rollback. It requires assertions and reports a skip if the OS disallows creating a test symlink.

`python tests/scripting/chat.py` compiles the production command hook and notification helper against native-call stubs. It checks exact command matching, owned payloads even if native code retokenizes, 256-byte limits, team flags, native delivery, custom-command handling, entity bounds, lobby/unloaded guards and balanced script string references. The GSC notification stack order is verified at the stub boundary; this is not a human's native chat session.

`powershell -NoProfile -ExecutionPolicy Bypass -File tests/scripting/status.ps1` loads only function definitions from `tools/server-status.ps1`. Network and Discord calls are replaced with mocks. Coverage includes first-run baseline, joins, leaves, empty rosters, offline/lobby/stale/wrong-map data, bounded history, formatting, dry-run behavior, failed/successful publication, atomic state saving and preservation of unrelated embed fields. Test files stay under a unique `build/tests/status-*` directory. Windows filesystem sandbox restrictions can deny `File.Replace`; the ordinary host run passes.

For an optional native test, copy `native.gsc` temporarily into the server's `s2x/scripts/mp/` directory alongside the shipped `s2x_server_events.gsc`. Enable a local roster filename with `s2x_roster_file`, run a bot match and inspect `ISSUE9 PASS` / `ISSUE9 FAIL` lines. Remove the test GSC and its `issue9-validation-*.txt` files after use. Do not copy it into release data.

Verified September 21, 2026: the combined Release x64 build loaded both scripts in a local dedicated London Docks Domination match. Three native map initializations read/incremented the same saved counter; empty/missing checks passed each time. Twelve bot-IP checks and twelve player-to-level chat bridge checks passed, with no reported script runtime error. The roster JSON contained a fresh timestamp, the correct map and an empty human list despite four bots. A localhost-only status dry run produced the presence field without contacting Discord. The validation process and temporary fixtures were cleaned up. Evidence: `build/tests/scripting/dedicated-native.log` and `status-dryrun.log` (local, not distributed).

Still requires live confirmation: a real human's `say`/`say_team` entering through the native C++ hook, a remote human's IP, actual card publication, and join/leave behavior across the operator's network.
